# 지도 API 호출 기록과 선택적 재사용

## 기본 동작

관리자 → 설정 → 지도 API 사용 기록에서 주소 검색과 자동차 이동의 일별 호출 시도·재사용 건수를 확인합니다. 최근 기록은 최대 31일 범위로 다음 지도 요청 때 정리하며, 화면은 최근 14개 날짜/종류 행을 표시합니다. 주소·좌표·키는 통계에 나오지 않습니다.

하루 기본 한도는 두 API 합계 2,000회입니다. 한국 시간 자정에 새 날짜 예산이 적용되며 서버 재시작으로 횟수가 초기화되지 않습니다. 한도 초과는 429로 중단하며 이동 가능으로 간주하지 않습니다. 네이버 청구 수량이 아니라 서버가 예약한 호출 시도 수입니다. 실패·시간 제한으로 실제 전송하지 못한 시도도 포함될 수 있습니다.

`backend/.env`에서 기관 규모에 맞게 조정한 뒤 서버를 재시작합니다. 예를 들어 하루 최대 300회:

```dotenv
MAPS_DAILY_CALL_LIMIT=300
```

기본 기록 파일은 backend 실행 폴더의 `maps-usage.sqlite3`입니다. 위치·주소를 포함하는 선택적 캐시 결과는 기존 DATA_KEY로 암호화하고 검색 키도 HMAC 처리합니다. 원본 API 응답·경로 도형은 저장하지 않으며 필요한 주소 후보 또는 소요 시간만 저장합니다. `care.db` 트랜잭션과 별도여서 일정 잠금 중 기록 쓰기가 충돌하지 않습니다. 기록 파일을 삭제하면 사용량도 초기화되므로 운영에서는 파일을 보호하세요.

## 재사용 허용 조건

네이버 Maps 공개 약관 제7조 제11항에는 결과 데이터를 별도 저장·DB화하여 재사용하는 제한이 명시되어 있습니다. 이번 기능의 재사용 기본값은 **꺼짐**입니다. 호출 기록은 결과 데이터가 아닌 건수만 남기므로 기본 상태에서도 기록과 한도는 작동합니다.

해당 계약에서 결과 저장·재사용이 별도로 허용된 경우에만 다음 설정을 사용합니다. 단순히 API 키를 발급받은 것과 재사용 허용은 다릅니다.

```dotenv
MAPS_CACHE_ALLOWED=true
MAPS_ADDRESS_CACHE_SECONDS=86400
MAPS_ROUTE_CACHE_SECONDS=300
```

- 주소 검색: 연속 공백과 양끝 공백만 정규화해 같은 검색을 기본 24시간 재사용합니다. 다른 주소를 임의로 같은 주소로 합치지 않습니다.
- 자동차 이동: 출발·도착 좌표, 방향, 경로 옵션이 같은 조회를 기본 5분 재사용합니다. A→B와 B→A는 별도입니다. 시간 여유분은 저장하지 않아 설정 변경이 즉시 반영됩니다.
- 실패·잘못된 좌표·비정상 응답은 저장하지 않습니다. 만료 후 API가 실패하면 오래된 결과를 대체 사용하지 않습니다.
- 캐시 조회 전에도 로그인·역할·지도 전송 동의·지도 활성 설정을 검사합니다. 키를 변경하면 이전 결과와 구분됩니다.
- 저장 파일이 같으면 프로세스 재시작 후 재사용합니다. 동시 중복 조회는 한 프로세스 안에서 묶습니다. 여러 프로세스는 예산을 공유하지만 최초 중복 외부 호출까지 묶지는 않습니다. 기존 권장 실행 `--workers 1` 기준입니다.
- 만료 항목은 다음 지도 요청에서 삭제합니다. 파일은 최대 5,000개 결과로 제한합니다. 재사용을 끄면 다음 지도 요청에서 저장 결과를 지우고 호출 기록만 유지합니다.
- API 호출 없이 재사용한 횟수는 기록되지만 실제 요금 절감률이나 현장 교통 정확도를 보장하지 않습니다.

## 업데이트

이번 변경은 `backend/app`과 `mobile` 코드가 필요합니다. 기존 `.env`, `care.db`, DATA_KEY를 유지하고 서버와 앱을 재시작하세요. `maps-usage.sqlite3` 테이블은 처음 사용할 때 자동 생성하며 care.db 스키마 변경과 추가 패키지 설치는 없습니다. 모바일은 `npm start -- --clear`로 재시작합니다.

서버 파일을 열 수 없으면 기록을 건너뛰고 호출하지 않고 오류로 중단합니다. 다중 서버의 각기 다른 로컬 파일은 예산을 공유하지 않으므로 이 버전은 한 기관 서버의 로컬 디스크를 기준으로 합니다.
