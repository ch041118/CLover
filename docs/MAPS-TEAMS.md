# 담당 팀과 지도 기반 일정 및 처리 이력

## 담당 사회복지사 연결

관리자의 **담당 연결**에서 요양보호사와 승인된 사회복지사를 선택해 저장합니다. 사회복지사 한 명에게 여러 요양보호사를 연결할 수 있고, 요양보호사 한 명의 현재 담당자는 한 명입니다. 사회복지사·요양보호사 계정에서도 본인에게 해당하는 연결을 볼 수 있습니다.

신규 일정 제안·자동 스케줄러·변경은 담당 팀 요양보호사에게만 가능합니다. 다른 팀이나 미연결 요양보호사에게 제안하는 API 요청은 거절합니다. 기존 기록의 관리자를 임의로 바꾸지 않습니다. 처음 연결할 때 기존 활성 일정의 조율 담당자와 일치해야 합니다. 기존 연결을 변경·해제하려면 진행 중인 일정을 먼저 완료하거나 취소해야 합니다.

업데이트 직후에는 기존 요양보호사의 팀 연결을 관리자가 지정해야 새 제안이 가능합니다. 연결하지 않았다고 기존 일정·수행 기록을 삭제하지 않습니다.

## 주소와 출발 시간

어르신·요양보호사의 **설정**에 방문지 또는 출발지 설정을 추가했습니다.

1. 지도 서비스의 주소·좌표 전송 안내를 확인하고 동의합니다.
2. 도로명 주소를 검색하고 결과를 선택합니다. 동호수는 검색에 넣지 않습니다. 좌표를 알고 있으면 직접 입력할 수도 있습니다.
3. 요양보호사는 매일 출발 가능한 시각을 입력합니다. 기본값은 08:00이며 한국 시간입니다.
4. 위치·동의 설정을 저장합니다. 기존 활동 지역과 근무 가능 시간도 따로 등록해야 합니다.

자동 GPS 추적은 하지 않습니다. 저장 좌표는 암호화합니다. 주소 검색 시 주소가, 이동 시간 계산 시 출발·도착 좌표가 네이버에 전달됩니다. 이름·상담 원문·건강 기록·회원 ID는 길찾기 요청에 넣지 않습니다. 클라우드 AI로 돌봄 내용을 보내는 기능과는 별개입니다.

당일 이후 진행할 일정 또는 당일 완료 기록이 있으면 위치·출발 시각을 변경하지 못하게 해 이동 기준이 바뀌는 것을 막습니다. 동의 철회는 같은 좌표와 출발 시각을 유지한 채 언제든 저장할 수 있습니다. 철회로 기존 확정 일정을 취소하지는 않으며 이후 이동 검증은 보류될 수 있습니다.

## 이동 시간을 고려한 일정

네이버 Directions 5의 자동차 소요 시간에 기본 15분의 여유 시간을 더합니다.

- 앞 방문이 있으면 그 어르신의 방문지에서 새 방문지까지 이동 시간을 확인합니다.
- 당일 첫 방문이면 요양보호사 출발지와 출발 가능 시각을 사용합니다.
- 뒤 방문이 있으면 새 방문을 끝내고 뒤 방문지까지 제때 도착할 수 있는지 확인합니다.
- 수락 대기·확정·진행 일정도 시간 점유에 포함합니다. 같은 날 완료·특이사항 보고 기록 역시 이동 순서에 반영합니다.
- 요청 검토 화면에서 후보를 선택한 뒤 **선택한 일정의 이동 시간 확인**으로 예상 시간을 볼 수 있습니다.
- 어르신의 직접 신청, 사회복지사의 제안·변경·확인, 1차 자동 제안, 요양보호사의 수락 시에도 이동 조건을 검사합니다.

스케줄러는 현재 접수순 요청과 시간순 후보에서 이동 가능한 첫 일정을 제안합니다. 전체 방문 순서를 재배치하는 최적화 알고리즘은 아닙니다. 3차 긴급 요청도 다른 일정을 밀어내지 않습니다. 지도 연동이 꺼져 있으면 기존 지역·시간 기반 방식으로 동작하며 이동 시간 미검증으로 안내합니다.

연동을 켠 상태에서 API 키·위치·동의가 없거나 API 오류가 나면 이동 가능으로 통과시키지 않습니다. 1차 자동 제안은 해당 요청을 미연결로 남기고 사유를 표시합니다. 개별 제안·수락은 오류를 보여 줍니다. 한 작업의 지도 조회는 최대 12회·약 12초의 시작 예산을 두고, 동일 구간은 그 작업 안에서만 재사용합니다. 마지막 요청의 네트워크 대기 시간이 추가될 수 있습니다.

현재 지원 범위는 **자동차**, **고정된 방문지·출발지**, **조회 시점의 교통 상황**입니다. 미래 출발 시각의 교통 예측, 대중교통·도보, 이동 중 GPS, 귀가 경로, 여러 날 출장, 요양보호사 자격·업무량 최적화는 미구현입니다. 방문일이 멀면 출발 전에 다시 확인해야 합니다.

## 사회복지사와 관리자의 처리 이력

**처리 이력** 메뉴를 추가했습니다.

| 사용자 | 조회 범위 |
|---|---|
| 관리자 | 단일 기관의 전체 돌봄 일정과 처리 기록 |
| 사회복지사 | 현재 담당 팀의 요양보호사 일정 또는 본인이 조율한 과거 일정 |
| 요양보호사 | 기존 본인 일정·전달문·수행 화면 사용. 관리용 처리 이력 접근 불가 |

방문 시작일·종료일, 요양보호사 ID, 상태로 조회합니다. 완료·특이사항·거절·취소와 진행 중 상태를 구분합니다. 목록은 50건 단위이며 건수는 조건에 맞는 전체 기록을 집계합니다. 방문일 기준이므로 요청 접수일 기준인 기존 통계와 다릅니다.

상세 화면은 승인된 전달문, 수행 결과·보고 시각, 제안 단계·요양보호사·현재 제안 상태·제안 생성 시각·거절 사유를 보여 줍니다. 상담 원문 전체를 기관 관리자에게 새로 공개하지 않습니다. 조회 자체도 감사 기록에 남깁니다. 과거 팀 변경 이력이나 수락·거절 각각의 정확한 처리 시각을 모두 재구성하는 기능은 아직 없습니다.

## 설치와 API 설정

1. 서버를 중지하고 기존 DB와 암호화 키를 백업합니다. 최신 코드를 받은 뒤 backend의 기존 가상환경에서 실행합니다.

```bat
python manage.py init-db
```

`caregiver_teams`, `route_locations` 테이블을 추가하며 기존 DB를 삭제하지 않습니다.

2. 네이버 클라우드 콘솔에서 Maps의 Directions 5와 Geocoding 사용이 가능한 애플리케이션 및 API 키를 준비합니다. 사용량·요금·서비스 접근 허용 설정은 해당 콘솔에서 확인합니다. 앱이 자동으로 키를 발급하거나 유료 서비스를 신청하지 않습니다.

3. **backend/.env**에 아래 항목을 설정합니다. 기존 JWT_SECRET과 DATA_KEY는 그대로 유지합니다.

```dotenv
ROUTING_ENABLED=true
NAVER_MAPS_KEY_ID=발급받은_API_Key_ID
NAVER_MAPS_KEY=발급받은_API_Key
TRAVEL_BUFFER_MINUTES=15
```

키는 모바일의 EXPO_PUBLIC 변수나 소스에 넣지 않습니다. 서버 재시작이 필요합니다. 지도 연동을 사용하지 않으려면 `ROUTING_ENABLED=false`로 설정합니다.

4. 서버와 모바일 앱을 재시작합니다. mobile에서는 `npm start -- --clear`를 실행합니다. 관리자가 담당 팀을 연결하고, 각 당사자가 지역·위치·동의·가능 시간을 등록한 후 가상 일정으로 검사합니다.

실제 네이버 API 키가 제공되지 않아 실제 계정 호출은 미검증입니다. 자동 테스트는 네이버 형식의 모의 응답으로 시간 부족·오류·동의·권한 조건을 검사합니다. 운영 전 실제 키·주소·이동 경로와 실기기 조작을 확인해야 합니다.
