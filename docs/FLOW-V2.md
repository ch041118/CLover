# 마이크 하나·자동 배정 개편 사용 안내

2026-09-25 · 코드 구현 기준. 현장 운영 검증 완료를 뜻하지 않습니다.

## 바뀐 흐름

어르신 기기를 한 번 연결하면 큰 마이크와 안내 한 줄이 표시됩니다. 누른 채 말하고 손을 떼면 저장 요청을 보내며, 서버 저장 성공 후 음성으로 접수를 알립니다. 음성 인식·일정 검사는 저장된 작업을 서버가 순서대로 처리합니다. 직원 설정에서 누르기 한 번으로 시작·종료하는 방식도 선택할 수 있습니다.

요양보호사가 미리 동의한 업무·활동 지역·빈 근무 시간 안에서, 이용자 희망 시간과 앞뒤 이동 시간을 검사해 일반 요청을 자동 확정합니다. 사회복지사의 건별 승인과 요양보호사의 건별 수락은 이 경우 필요 없습니다. 수행 불가 사유가 등록되면 담당 사회복지사의 ‘개입 필요’ 업무함으로 이동합니다. 사회복지사가 새로 제안한 일정은 요양보호사가 수락하거나 거절합니다.

## 기존 Windows 설치 업데이트

서버를 종료하고 기존 `backend/.env`, 데이터베이스, 모델 폴더를 백업합니다. 특히 DATA_KEY를 바꾸면 기존 암호화 자료를 읽을 수 없습니다. 이번 변경은 새 테이블 추가이며 기존 테이블 컬럼을 삭제하지 않습니다.

최신 소스 폴더의 backend에서 실행합니다. 가상환경이 없다면 먼저 `python -m venv .venv`를 실행하세요.

```bat
.venv\Scripts\activate
python -m pip install -r requirements.txt
python manage.py init-db
```

음성 모델이 아직 없다면 [음성 설치 안내](UPGRADE-VOICE-MATCHING.md)의 requirements-speech 설치와 모델 다운로드를 먼저 진행합니다. `.env`에는 기존 JWT_SECRET·DATA_KEY·지도 키를 유지하고 다음 설정을 확인합니다.

```dotenv
LLM_MODE=local
LOCAL_MODEL=qwen2.5:0.5b
LOCAL_MODEL_URL=http://127.0.0.1:11434
LOCAL_PRIVACY_REVIEWED=true
SPEECH_ENABLED=true
SPEECH_MODEL_PATH=./models/whisper-tiny
ROUTING_ENABLED=true
FLOW_WORKER_ENABLED=true
FLOW_PUSH_ENABLED=false
```

LOCAL_PRIVACY_REVIEWED는 기존 로컬 모델 운영 설정을 확인한 후 켭니다. 지도 키 설정은 [MAPS-TEAMS.md](MAPS-TEAMS.md)를 따릅니다. 주소 검색과 경로 검증이 성공해야 일반 요청이 자동 배정됩니다. 지도 설정이 없거나 검증에 실패하면 사회복지사 확인 대상으로 남습니다.

첫 번째 cmd에서 모델 서버를 켭니다.

```bat
python start_local_model.py
```

두 번째 cmd에서는 backend 가상환경을 활성화하고 API를 켭니다. 작업 큐와 푸시의 현재 권장 구성은 서버 프로세스 한 개입니다.

```bat
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --no-access-log --workers 1
```

세 번째 cmd는 mobile 폴더에서 실행합니다.

```bat
npm ci
npx expo start --clear
```

mobile/.env의 EXPO_PUBLIC_API_URL은 휴대폰에서 접근 가능한 PC의 현재 IPv4 주소를 사용합니다. localhost는 휴대폰 자신을 뜻합니다. 개발용 HTTP 허용 설정은 기존 [MOBILE.md](MOBILE.md)를 따릅니다. Windows 방화벽의 사설 네트워크와 포트 8000, PC·휴대폰의 상호 통신도 확인합니다.

SecureStore·알림 네이티브 모듈이 추가됐으므로 기존 개발 빌드를 사용한다면 다시 빌드·설치해야 합니다. Expo Go 실행 검사와 실제 원격 푸시 검사는 구분합니다. 푸시에는 실제 EAS 프로젝트 ID, 플랫폼 푸시 자격증명과 호환되는 개발/배포 빌드가 필요합니다.

## 최초 운영 설정 순서

1. 관리자가 사회복지사와 요양보호사 가입을 승인하고 ‘담당 연결’에서 팀을 연결합니다.
2. 요양보호사가 활동 지역, 근무 가능 시간, 지도 전송에 동의한 출발지를 등록합니다. 설정에서 자동 배정 동의와 가능한 업무를 저장합니다.
3. 요양보호사의 ‘어르신 등록’에서 이름·지역·도로명 주소 검색 결과를 저장합니다. 이용자에게 음성·로컬 AI와 위치 전송을 설명하고 동의를 확인합니다. 담당 사회복지사는 요양보호사의 팀에서 연결됩니다.
4. 등록 목록에서 기기 연결 코드를 발급합니다. 어르신 휴대폰의 최초 화면에 직원이 코드를 입력하고 마이크 권한을 허용합니다. 코드는 10분 동안 한 번만 사용할 수 있으며 새 코드 발급은 이전 기기를 해제합니다.
5. ‘내일 오후 두 시에 청소 도와줘’와 같이 시험 요청을 보내고 접수 음성, 배정 음성, 요양보호사 일정을 확인합니다.
6. 수행 불가 사유를 남겨 사회복지사 업무함에 나타나는지 확인하고, 빈 일정을 선택해 다시 제안합니다. 요양보호사 수락 이후 방문 수행·보고까지 확인합니다.

기존 어르신 계정은 ‘기존 이용자 연결’을 사용할 수 있습니다. 담당 사회복지사가 이미 맡은 기존 요청이 있는 승인 계정만 연결할 수 있습니다. 기존 이용자의 AI·지역·주소 설정도 먼저 확인하세요. 직원 화면으로 돌아가려면 어르신 화면 상단 CLover를 길게 누릅니다. 직원 계정 로그인은 별도로 필요합니다.

## 자동 배정 규칙

| 항목 | 현재 구현 |
| --- | --- |
| 일반 업무 | 식사 45분, 집안일 30분, 말벗 30분, 이동 동행 60분 |
| 시간 없음 | 접수 시각 5분 뒤부터 7일 이내 가능한 시간 탐색 |
| 명시한 시간 | 해당 시각을 지킴. 불가능하면 임의 변경 없이 담당자 확인 |
| 오전·오후 범위 | 오전 09–12시, 오후 12–18시 안에서 탐색 |
| 불명확한 말 | 한 번 다시 말해 달라고 요청. 재차 불명확하거나 10분 응답 없으면 담당자 확인 |
| 후보 평가 | 같은 팀·지역·동의 범위 후보 중 최대 6명/슬롯 검사, 요청당 경로 호출 예산 12회 |
| 우선순위 | 가능한 시작 시각, 검증한 이동 시간, 기존 배정 수 |
| 긴 근무 시간 | 필요한 방문 길이만 예약하고 앞뒤 남은 시간은 별도 빈 슬롯으로 유지 |
| 반복 미해결 | 최근 7일 미해결 요청 2건이 이미 있으면 새 요청을 사람 확인으로 전환 |
| 복약·기타·위험·복잡한 변경 | 자동 배정하지 않고 담당 사회복지사에게 전달 |
| 취소 | ‘방금/최근 요청 취소’이며 취소 대상이 하나로 특정되는 경우만 자동 처리 |

기관 운영값을 화면에서 모두 바꾸는 기능은 아직 없습니다. 방문 길이는 flow_service.py, 시간 해석은 intent.py에 정의돼 있습니다. 모든 자연어 날짜·시간 표현을 지원하지 않습니다. 병원 도착 시간과 출발 시간이 혼동될 수 있는 표현도 담당자가 확인합니다.

## 이력·알림·장애 처리

사회복지사는 담당 팀의 개입 요청과 전체 처리 내역을 조회하며 관리자는 ‘자동 처리 내역’에서 전체 이력과 분류별 상태 건수를 조회합니다. 목록은 최신 100건, 통계는 전체 데이터 기준입니다. 다시 말하기로 대체된 접수는 통계에서 제외하며 취소 발화 접수는 별도 건으로 포함합니다. ‘사람 개입 없이 완료’는 worker_adjust/close/cancel 이력이 없는 완료 건입니다. 실제 절약된 노동 시간을 측정하는 지표는 아닙니다.

음성 작업과 처리 단계는 DB에 저장하며 중단된 작업은 임대 기한이 지난 뒤 회수합니다. 최대 3회 기술 오류 재시도 후 담당자에게 넘깁니다. 같은 요청 키를 재전송하면 새 방문을 만들지 않습니다. 원음은 암호화된 작업 자료로 잠시 저장하고 처리·예외 전환 때 삭제합니다. 처리 원문과 사유는 암호화 저장됩니다.

앱 알림함은 15초 간격으로 갱신합니다. 방문 30분 전까지 미확인 알림이 남거나 시작 시각 15분 뒤까지 시작 기록이 없으면 담당자 확인 대상으로 전환합니다. 서버를 계속 실행해야 검사됩니다.

원격 푸시는 기본 꺼짐입니다. 실제 EAS 구성을 한 빌드에서 직원이 ‘휴대폰 알림 연결’을 누르고 서버 FLOW_PUSH_ENABLED=true를 설정해야 시도합니다. 이름·주소·요청 원문은 푸시 본문에 넣지 않습니다. Expo 접수 성공(submitted)은 휴대폰 실제 도착 증명이 아니며 receipt 후속 확인은 아직 없습니다. 다중 작업자의 푸시 중복 방지는 후속 과제입니다.

## 남은 현장 검증과 범위

- 실제 Android/iPhone에서 길게 누르기, 빠른 손 떼기, 앱 전환, 재실행, 기기 연결·해제, 음성 재생을 검증해야 합니다.
- 실제 Whisper·Qwen 한국어 인식률, 처리 시간과 실제 네이버 경로 응답은 자동 테스트의 모의 응답과 다릅니다. 모델을 매번 로드하는 기존 방식은 유지돼 PC 처리 시간 개선을 보장하지 않습니다.
- 새 어르신 화면은 마이크 접수에 집중합니다. 기존 자동 안부 질문 컴포넌트는 현재 이 화면에 연결되지 않았으며 상시 백그라운드 음성 확인도 지원하지 않습니다.
- 등록 후 어르신 주소·담당 팀 일괄 변경, 고급 자연어 변경, 정기 방문, 전체 동선 최적화, 운영 PostgreSQL 부하·다중 서버 검증은 남아 있습니다.
- 기기 연결 비밀은 SecureStore에 저장하고 서버에는 해시만 보관합니다. 연결 유효기간은 90일이며 이후 직원 재연결이 필요합니다.
- 앱 강제 종료 직전 서버에 도착하지 않은 녹음은 복구하지 않습니다. 저장 성공 전에 접수됐다고 안내하지 않습니다.
