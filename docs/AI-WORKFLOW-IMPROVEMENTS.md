# 사회복지사 업무 경감 중심 개선

기준일 2026년 9월 20일. 서비스의 목표는 사회복지사가 직접 하던 접수 정리·분류·전달 준비의 일부를 AI가 먼저 수행하고, 사회복지사가 검토와 개입에 집중하도록 하는 것이다.

## 부족했던 점과 이번 개선

| 부족했던 점 | 이번에 바꾼 기능 | 줄이려는 작업 |
|---|---|---|
| AI가 위험도만 제시하고 원문을 정리하지 않음 | 접수 시 한 번의 로컬 모델 호출로 분류·짧은 요약·원문 근거 준비 | 원문에서 핵심을 찾고 다시 정리하는 작업 |
| 미배정 건을 하나씩 맡고 화면을 이동함 | 최대 20건 담당 접수와 AI 업무함을 기본 화면으로 제공 | 반복 접수 버튼과 메뉴 이동 |
| 모든 요청을 같은 검토 목록에서 처리함 | 일반 확인 후보와 직접 개입 대상을 나누고 이유 표시 | 우선순위 판단과 예외 탐색 |
| 일반 요청도 각각 분류를 저장해야 함 | 확인한 일반 요청을 최대 20건 묶어 승인 | 반복 분류·저장 작업 |
| 개별 요청을 요양보호사에게 전달할 자료가 없음 | 도움 종류와 원문 발췌로 전달문 준비, 담당자가 수정·승인 | 전달문을 처음부터 작성하는 작업 |
| AI가 도움이 됐는지 측정할 자료가 없음 | AI안 그대로 승인·수정 승인·묶음 승인 건수 기록 | 효과를 추정에만 의존하는 문제 |

전달문은 AI가 검증되지 않은 지시를 새로 쓰는 방식이 아니라, 도움 종류와 검증한 원문 발췌를 조합한다. AI 요약은 담당자 검토용이며 전달문으로 자동 복사하지 않는다. 원문 근거가 실제 입력에 없는 경우 AI 정리 완료로 취급하지 않는다.

## 새로운 업무 흐름

1. 어르신이 접수하면 저장된 동의 설정에 따라 로컬 AI가 분류·요약·근거를 함께 생성한다. 별도의 두 번째 추론은 추가하지 않는다.
2. 사회복지사는 **AI 업무함**에서 미배정 요청을 최대 20건 맡는다. 기존 담당자의 요청은 가져오지 않는다. 담당 전에는 원문을 공개하지 않는다.
3. 업무함에서 요약, 원문, 근거 발췌, 전달문과 확인 사항을 함께 본다. 긴급 건을 먼저 표시한다.
4. 일반 후보는 원문·분류·전달문을 검토한 뒤 선택해 묶음 승인한다. 수정한 건이나 개입 대상은 개별 승인한다.
5. 승인하면 분류 검토와 전달문 저장을 함께 마친다. **일정 관리**의 1차 자동 제안 또는 **요청 검토**의 직접 일정 연결로 진행한다.
6. 연결된 요양보호사는 승인된 전달문을 보고 일정을 수락하거나 거절한다. 일정 확정과 방문 시작 조건은 유지한다.

**자동 실행 범위:** 접수 시 정리와 전달문 준비는 자동이다. 담당 가져오기, 검토 승인, 1차 스케줄러 실행은 사회복지사가 누른다. AI가 임의로 담당자를 선정하거나 방문을 확정하지 않는다.

## 묶음 승인 조건과 개입 지점

묶음 승인은 담당자가 확인한 요청에만 적용한다. 로컬 AI 정리가 완성되고 분류가 불확실하지 않으며, 긴급·건강·상담 관련 확인 신호가 없고, 이용자의 지역이 등록되어 있어야 한다. 현재 위험 신호 탐지는 규칙이므로 누락 가능성이 있고, 모델 신뢰도도 실제 정확도를 보장하지 않는다. 따라서 원문 확인을 건너뛰는 무인 처리 조건이 아니다.

다음 요청은 개별 확인 대상으로 남긴다.

- 긴급 분류 또는 AI 분류가 불확실한 요청.
- 동의 없음, 모델 꺼짐·실패, 불완전 요약이나 원문에 없는 근거.
- 복약·기타 종류, 추가 위험 신호, 건강·상담 관련 표현이 있는 요청.
- 같은 어르신·같은 종류가 최근 7일에 3회 이상인 반복 요청.
- 이용자 지역이 등록되지 않은 요청.

검토하는 사이 반복 요청이 추가되거나 지역·분류 상태가 바뀌면 기존 화면의 승인 요청을 거절하고 새로고침하도록 한다. 묶음 중 한 건이라도 조건이 바뀌면 전체를 저장하지 않는다. 이미 승인된 요청을 중복 승인하지 않는다.

## 전달문과 기록

요약과 근거는 기존 요청 암호문 안에 저장한다. 승인된 전달문과 검토 결과는 새 `care_decisions` 테이블에 저장하며 전달문은 암호화한다. 연결된 요양보호사만 제안·확정·수행 단계에서 승인된 전달문을 볼 수 있다. 요청 원문 전체와 검토되지 않은 초안은 전달하지 않는다. 이름과 주소가 발췌에 남을 수 있으므로 승인 전에 필요한 정보만 남기도록 편집한다.

기존 요청은 선택 항목 기반 정리로 표시하고, 동의 없이 과거 기록을 다시 AI에 보내지 않는다. 기존 검토 화면에서 분류를 다시 수정하면 이전 승인 전달문은 비공개로 바뀐다. 새 업무함은 아직 검토하지 않은 담당 요청을 한 페이지 최대 50건 보여준다.

## 효과 측정과 남은 과제

내가 최근 30일에 검토한 요청의 최신 결과를 기준으로 총 검토 수, AI 정리 수, AI안 그대로 승인 수, 수정 승인 수, 묶음 승인 수를 집계한다. 동일 요청을 다시 검토하면 최신 결과로 갱신한다. 절감 시간이나 AI 정확도를 실제 측정한 수치는 아니다.

우선 과제는 실제 사회복지사의 접수당 소요 시간과 수정 이유를 측정하고, 어르신 희망 시간을 구조화해 추가 확인을 줄이는 것이다. 이후 승인 후 일정 제안을 더 직접 연결하고, 알림·응답 기한, 승인된 전달문 수정과 버전 이력, 기관별 자동 담당 규칙을 보완할 수 있다. 현재 입력만으로 도움 종류를 다시 분류하거나 자격·이동 시간을 최적화하는 기능은 포함하지 않았다.

작은 로컬 모델의 한국어 요약 품질과 확대된 출력의 지연 시간은 사용자 PC에서 검증해야 한다. 이번 변경은 작업 준비와 반복 조작을 줄이는 구현이며, 실제 업무 감소율은 시범 운영 전에는 확정할 수 없다.

## 업데이트

기존 DB와 암호화 키를 백업하고 서버를 중지한 뒤 backend의 가상환경에서 실행한다.

```bat
python manage.py init-db
```

새 `care_decisions` 테이블만 추가하며 기존 암호화 키를 유지한다. 서버를 재시작하고 mobile에서 `npm start -- --clear`를 실행한다. 로그인 후 사회복지사의 기본 화면은 AI 업무함이다.
