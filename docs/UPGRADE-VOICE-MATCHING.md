# 생활 돌봄·음성·지역 일정 연결 업데이트

## 달라진 사용 흐름

- 홈은 생활 도움 요청과 돌봄 일정 찾기를 중심으로 구성했습니다.
- 식사 준비, 산책·외출 동행, 가벼운 집안일, 장보기, 이야기 나누기, 약 시간 챙기기를 먼저 표시합니다. 긴급 항목은 별도로 펼치며 기존 긴급 규칙은 유지합니다.
- 처음 로그인하면 AI 분석 안내를 보고 사용 여부를 한 번 정합니다. 이후 접수에는 저장된 설정을 적용합니다. 선택 전에는 분석하지 않으며 설정에서 철회할 수 있습니다. 접수에 동의를 강제하지 않습니다.
- 안내문은 로컬 AI로 작성하고 직접 편집할 수 있습니다. AI가 꺼져 있거나 실패하면 준비된 기본 문구를 표시합니다. `source=template`을 AI 작성으로 표시하지 않습니다. 모델 출력 예산도 192 → 384토큰으로 조정했습니다. 사용자 PC에서 발생한 오류 로그는 제공되지 않아 당시 원인을 확정한 것은 아닙니다.

## 기존 Windows 설치 업데이트

1. 실행 중인 서버와 앱 개발 서버를 Ctrl+C로 종료합니다.
2. 기존 `backend/.env`, `backend/care.db`와 DB 백업을 보관합니다. 암호화 키를 새로 생성하지 마세요.
3. GitHub의 최신 코드를 가져오되 기존 `.env`와 DB는 유지합니다. ZIP으로 받았다면 새 폴더의 backend에 기존 파일을 옮긴 뒤 실행합니다. 기존 mobile/.env도 유지하세요.
4. backend에서 다음을 실행합니다.

```bat
.venv\Scripts\activate
python -m pip install -r requirements.txt
python manage.py init-db
```

새 폴더에 가상환경이 없다면 먼저 `python -m venv .venv`를 실행합니다. `init-db`는 새로운 preferences/service_regions/availability/bookings 테이블만 추가하며 기존 users/care_logs 컬럼은 변경하지 않습니다. 운영 PostgreSQL에서도 서비스 재시작 전에 같은 명령으로 테이블을 생성합니다.

5. mobile에서 `npm ci`를 실행합니다. `.env`의 API 주소는 기존 PC 주소를 유지합니다.
6. 기존 방법대로 Ollama·백엔드를 켜고 mobile에서 `npm start -- --clear`를 실행합니다. Expo Go는 SDK 57 호환 버전이 필요합니다. 직접 만든 개발 빌드를 쓰고 있었다면 expo-audio 네이티브 권한/모듈이 추가되어 개발 빌드를 다시 설치해야 합니다.

## 음성 인식 설치 (기관 PC에서 한 번)

일반 요청 분석은 기존 Qwen2.5 0.5B, 음성을 글로 바꾸는 작업은 **faster-whisper의 다국어 tiny 모델, CPU int8**을 사용합니다. 음성 인식에는 별도 모델이 필요합니다. 작은 모델이라 사투리·작은 목소리·배경 소음에서 인식 오류가 날 수 있습니다.

backend 폴더에서 실행합니다.

```bat
.venv\Scripts\activate
python -m pip install -r requirements-speech.txt
python download_speech_model.py
notepad .env
```

설정에 다음을 추가합니다.

```dotenv
SPEECH_ENABLED=true
SPEECH_MODEL_PATH=./models/whisper-tiny
```

다운로드는 설치 단계에서만 인터넷을 사용합니다. 실데이터를 받기 전에 다운로드를 완료하세요. 서버를 재시작해야 설정이 반영됩니다. 앱 설정에 ‘모델 준비됨’은 파일 존재 확인이며 실제 인식 성공을 보장하지 않습니다.

요청 처리 시에는 로컬 경로·`local_files_only=True`와 오프라인 환경을 사용하며 모델을 자동 다운로드하거나 외부 음성 API로 전환하지 않습니다. CPU 추론은 별도 프로세스에서 최대 50초, 녹음은 서버 기준 최대 45초·2MB로 제한합니다. 텍스트 모델과 같은 추론 슬롯을 사용하므로 동시에 들어온 다른 AI 요청은 대기 대신 담당자 확인 또는 재시도 안내가 됩니다. 음성 모델은 요청마다 로드 후 종료되어 메모리를 회수하며 저사양 PC에서는 느릴 수 있습니다.

다운로드 후에는 기관 정책에 따라 Python/Ollama 프로세스의 외부 송신도 차단하세요. 오프라인 라이브러리 설정만으로 장비 전체의 통신을 통제하는 것은 아닙니다. 원문 음성과 변환 글은 기관 서버로 전송됩니다. 운영에는 HTTPS가 필요합니다.

## 어르신의 말로 접수

1. 도움 요청 → ‘안내에 동의하고 말하기’. 처음에는 휴대폰 마이크 권한도 허용합니다.
2. 필요한 도움을 말합니다. 25초 후 자동 종료하며 일찍 마치면 기다리면 됩니다.
3. 기관 PC에서 변환한 내용을 화면에서 확인합니다. 잘못 들었다면 ‘내용 다시 말하기’를 누릅니다.
4. ‘말로 확인·접수’를 누르고 **“접수해 주세요”**라고 말하면 7초 후 확인해서 접수합니다. “취소해 주세요”는 접수하지 않습니다.
5. 애매한 말·무음은 자동 접수하지 않습니다. 통신이 끊기면 내 요청에서 접수 여부를 확인한 뒤 다시 시도합니다.

타이핑 없이 사용할 수 있지만 마이크 시작과 음성 확인 버튼은 눌러야 합니다. 계속 듣는 호출어 기능이나 음성 읽어주기는 포함하지 않습니다. 앱이 배경으로 가거나 화면을 벗어나면 녹음을 중단합니다. 녹음은 앱 캐시에서 처리 후 삭제하고 서버에서는 메모리/파이프로만 처리합니다. 비정상 강제 종료 시 남을 수 있는 기기 캐시는 기관의 기기 관리 대상입니다. 실제 어르신 음성의 인식률과 Android/iPhone 마이크 흐름은 실기기 검증이 필요합니다.

## 지역과 일정 연결

- 어르신: ‘돌봄 연결’에서 도움받을 지역을 추가하고 날짜·시간 범위를 선택합니다.
- 요양보호사: ‘근무 일정’에서 활동 지역을 추가하고 가능한 날짜·시작·종료 시간을 등록합니다. 여러 지역/일정을 등록할 수 있습니다.
- 지역은 시·도를 선택하고 시·군·구를 직접 입력합니다. 두 사용자의 시·도와 시·군·구 명칭이 같아야 검색됩니다. 자동 위치 추적·GPS·거리 계산·주소 보정은 사용하지 않습니다. ‘수원시 영통구’처럼 같은 표기를 사용하세요. 상세 주소는 입력하지 않습니다.
- 검색 결과는 원하는 시간 범위에 전체가 들어오는 근무 일정입니다. 일정 전체를 신청하며 부분 분할 예약은 하지 않습니다. 한국 시간 기준 미래 90일까지 지원합니다.
- 어르신 신청 → 요양보호사 수락 → ‘일정 확정’. 거절·취소하면 미래 일정은 다시 신청 가능해집니다.
- 요양보호사의 겹치는 일정 등록, 동일 일정 동시 예약, 어르신의 겹치는 신청을 차단합니다.
- 지역을 삭제해도 기존 신청 기록을 삭제하지 않습니다. 확정된 일정은 별도 취소해야 합니다.
- 승인된 계정만 이용하며 자신과 연결된 신청만 조회합니다. 상대방에게는 계정 ID·지역·시간·도움 종류만 보입니다. 기존 상담/돌봄 원문은 공유하지 않습니다.
- 푸시·문자 알림은 아직 없으므로 ‘일정 상태 새로고침’으로 확인합니다. 실제 방문의 상세 장소 조율, 자격 확인, 비용 정산은 기관 절차로 진행해야 합니다. 다기관 분리·반복 일정·이동 시간 계산은 이번 범위에 포함하지 않습니다.

## 안내문이 기본 문구로 나오는 경우

앱의 설정에서 서버 AI가 켜졌는지 확인하세요. backend/.env에서 기존 네 값을 유지해야 합니다.

```dotenv
LLM_MODE=local
LOCAL_MODEL=qwen2.5:0.5b
LOCAL_MODEL_URL=http://127.0.0.1:11434
LOCAL_PRIVACY_REVIEWED=true
```

전용 cmd에서 `python start_local_model.py`를 실행한 뒤 다른 cmd에서 `python check_local.py`를 실행합니다. 이 검사는 기본 문구로 대체하지 않고 실제 AI의 연결·출력 형식을 확인합니다. 앱에서는 실제 AI 성공과 기본 문구 대체를 구분하여 표시합니다.
